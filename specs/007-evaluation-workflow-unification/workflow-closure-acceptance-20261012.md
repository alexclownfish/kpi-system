## 本次手工验收问题闭环

1. **PDF 缺少加权贡献值和评分等级**：单份 PDF、批量签字 PDF 和 Excel 现在共用同一个 `exportDocument` 字段链路。默认签字版式包含“加权贡献”和“评分等级”，评分等级同时出现在结果摘要；模板导出设置可以继续增删字段。已有 weighted-v2 完成考核如果历史快照缺少这些字段，导出时从不可变的最终计算结果补齐，不改快照 ID、校验码或已冻结版式。
2. **纸质签字入口消失**：新版流程的最终确认状态是 `awaiting_employee_confirmation`，页面此前只识别旧状态 `pending_confirm`。入口现在兼容两种状态；登记成功后进入 `completed`，入口隐藏并显示已归档材料下载。已完成在线确认或存在未处理异议时不会重复显示入口。
   员工在线确认后，`completed` 详情页继续显示“补充纸质签字”操作。该操作新增独立补充材料记录和 `upload_signoff_supplement` 审计，不修改完成状态、原确认或最终结果；详见 [signoff-supplement-acceptance-20261013.md](./signoff-supplement-acceptance-20261013.md)。
3. **`ORPHAN_SCORING_TASKS` 为 7**：这是旧删除逻辑遗留的孤立评分任务，不是当前新版评分流程持续产生。审计保持只读，不自动删除历史数据；现在会返回数量及最多 20 个样本 ID 供管理员备份后精准处理。当前删除事务已覆盖评分任务、计算结果、快照、确认、评论、邀请和签字附件，后续删除不会继续制造同类孤儿。

## 本轮回归覆盖

1. 线上确认或纸质签字完成后，所有评分任务写入都返回 `TASK_LOCKED` 或 `SCORING_WORKFLOW_STATE`；已提交任务保持 `submitted`，只增加锁定时间和版本，最终计算结果/快照总分不变。
2. 删除考核在单事务内清理评分任务、旧评分、计算结果、结果快照、确认、评论、邀请及邀请评分，并删除纸质签字附件。
3. 删除模板同时清理维度和指标。
4. 审计发现非法年月/季度、completed 状态缺最终结果或确认、伪造总分、旧流程最终明细不一致，以及七类孤立工作流记录；缺表读取错误也会形成 error finding。范围审计员不会看到全局孤立记录。
5. 导出单份/批量下载失败时不会提示成功；会显示错误码、请求 ID、结果版本和重试指引。备用窗口被拦截会明确提示允许弹窗后重试。
6. weighted-v2 导出包含维度、权重、综合权重、评分职责、实际评分人和加权贡献；默认签字栏由职责快照生成，自定义签字栏和历史布局保持不变。

## 页面验收方法（服务启动后）

1. 使用 HR 或系统管理员创建一条月度 weighted-v2 考核，确认评分任务中的评分人来自模板职责；录入一个 `0` 分并提交，确认零分不会被当成未评分。
2. 以评分人账号打开该考核，保存并提交评分；再由管理员推进到员工确认。进入评分任务页，确认所有任务显示已锁定，重复保存/提交会显示明确错误。
3. 以员工账号完成在线确认，或在详情页先导出结果再登记纸质签字。确认后刷新详情，验证总分、导出版本和签字快照一致。
4. 在模板导出设置中勾选“维度、维度权重、指标权重、综合权重、评分职责、实际评分人、加权贡献”，保存后导出 Excel 和 PDF，核对列名和数据一致；再复制新版本修改签字栏，确认旧考核导出不变。
5. 临时创建一条带附件的考核并删除，确认详情、评分任务、评论、签字附件均不再存在。不要使用清空数据库或删除 Compose 卷的方式测试。
6. 打开“考核审计”，执行预览，确认异常记录显示具体 finding code；`ORPHAN_SCORING_TASKS` 若仍为 7，应同时显示 `count` 和 `sample_ids`，这是历史遗留的只读提示；重复执行两次，确认结果稳定且业务数据数量不变。

7. 批量导出签字表，逐份打开 ZIP 内 PDF，确认其结果版本、校验码、字段列、评分职责签字栏和单份 PDF 一致，且页面为 A4 竖向；该入口现在复用单份结果导出渲染器，不再使用独立的旧 HTML/Chromium 模板。
