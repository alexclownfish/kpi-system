# Quickstart: 荭杏研发绩效模板导入与流程适配 v2

本文用于开发验收和用户页面验收。用户负责启动 Docker Compose；本 Feature 不要求清空数据库、删除卷或重新生成管理员密码。

## 1. 源文件校验（只读）

在项目根目录准备工作簿：

```text
/Users/simon/Downloads/荭杏研发项目绩效考核表 (1).xlsx
```

确认 SHA-256 为：

```text
50bcf21db2fb357a5a471ecef459353b974355c2b7191e3f920fa708c3735fb3
```

运行解析器诊断（实现后）：

```bash
python3 scripts/verify_source_workbook.py \
  "/Users/simon/Downloads/荭杏研发项目绩效考核表 (1).xlsx" \
  --output /tmp/hongxing-template-v2-report.json
```

验收报告至少应包含：21 张工作表、1 流程表、18 岗位模板、2 HR 汇总表、9 源部门、137 指标、源 SHA、shared formula 展开统计、维度内权重异常及季度 HR 公式断档。

## 2. HR 页面验收

1. 以具备模板维护权限的账号进入模板管理。
2. 打开新版工作簿校验/预览，确认来源 SHA、岗位/部门/指标计数和诊断列表可见。
3. 对原表点击“开始校验”，应显示 **21 张表 / 18 套模板 / 137 个指标 / 9 个部门 / 0 阻断 / 22 告警**。结构、电子、软件、产品模板的维度内合计异常仅告警；18 套模板综合权重均为 100，页面不能归一化原权重。
4. 全新来源保存为草稿后，新建模板必须为 draft/inactive；在模板列表选择草稿并发布。直接“导入并发布”会先要求确认告警，已有模板显示实际新增/复用数量；不同 SHA 的新版本会在同一事务中切换为当前版本，旧版本变 `retired` 并默认隐藏，历史考核不变。若同来源已经有草稿/停用版本，整批发布提示到模板列表显式处理，不假报全部发布。一次来源导入后重复按钮禁用；修改 Excel 重新选文件校验应显示新 SHA 和实际修改内容。
5. 修改已发布模板时确认页面要求复制新版本；原版本和引用它的历史考核仍可查看。
6. 打开 HR 汇总诊断，确认季度 I17/J17 为“空白预留行缺少公式”告警，保留来源定位。原表第 17 行仅有 A 列序号，B:H 均空；若在副本 B17 填姓名或 H17 填 0 后重新校验，缺公式应成为阻断，“导入并发布”禁用。
7. 若旧初始化留下 5 套草稿，本次修复只解除错误来源阻断并保留告警，不擅自改变草稿状态。到模板列表查看对应草稿，在计算结构中发布；已有考核继续使用原快照。
8. 模板列表默认只显示当前草稿和已发布版本；点击“显示历史版本”后才显示 retired 版本。未引用任何考核的停用版本可逐条删除，已被历史考核引用的版本必须保留。

## 3. 岗位匹配和评分验收

使用唯一前缀的私有测试员工和测试周期，不覆盖真实考核：

1. 为研发部门负责人、普通研发工程师、产品岗位各准备一名启用员工及其组织关系。
2. 创建考核前打开模板预览，确认按部门、岗位类型和月度周期命中唯一已发布模板。
3. 确认评分任务出现正确的 PM、部门负责人、CTO、产品经理职责；评分人即使 RBAC 是普通员工也能按业务职责看到自己的任务。
4. 只填写部分必填指标并点击进入员工确认，确认页面列出未完成指标且状态不改变。
5. 提交有效 `0` 分，确认它计入完成度，不被显示为空白或自动判为 D。
6. 完成所有必填指标后确认总分、等级、综合权重和加权得分；多个评分人的指标使用有效分算术平均。
7. 在评分人账号被停用或组织关系缺失的测试场景中创建考核，确认显示具体缺失职责且不产生半成品。
8. 以普通员工打开自己的新版考核，先尝试填写自评分，确认返回“请先提交工作总结与后续计划”；提交四项总结内容后才能进入自评分。
9. 以产品经理账号尝试在 PM 未提交时提交评分，确认返回评分顺位阻塞；PM 提交后再依次完成第二、第三顺位。

## 4. 历史快照和导出验收

1. 记录一份已完成考核的模板版本、来源 SHA、快照校验码、总分、等级和导出文件校验码。
2. HR 发布同岗位新模板版本并修改权重或字段。
3. 再次打开旧考核并导出 Excel、纵向 PDF 和批量签字 PDF，确认指标、权重、评分职责、总分、等级和签字字段与记录完全一致。
4. 新建同岗位考核，确认只使用新版本。
5. 在 `completed` 状态补充纸质签字材料，确认状态、总分、等级和原确认记录不变，并有追加审计记录。
6. 创建同一员工同一周期的两个项目考核，分别填写项目名称和投入占比；在统计分析中确认项目列表、汇总条数、加权贡献和年度加权结果。
7. 以系统管理员打开“考核审计”，只在确认孤立任务样本 ID 后点击“清理样本”，确认正常评分任务不删除且清理审计可见。

## 5. 自动化质量门禁

实现后按改动范围运行：

```bash
python3 scripts/test_source_workbook.py "/Users/simon/Downloads/荭杏研发项目绩效考核表 (1).xlsx"
(cd server && go test ./...)
npx tsc --noEmit
npm run build
node --test tests/unit/*.test.mjs
docker compose config
```

用户启动服务后再执行：

```bash
docker compose up -d --build &&
curl -f http://localhost/health
```

只有构建成功才继续检查健康状态。构建失败时旧容器可能继续提供 `/health`，返回 OK 不代表更新已部署；`buildx` 插件缺失的警告也不等于构建失败，以具体 `FAIL` 和命令退出码为准。

若本地端口由 `.env` 或反向代理改变，以实际页面地址访问；不要为了验收修改生产 `.env` 或清理持久化卷。

## 6. 安全清理

验收完成后仅删除带唯一前缀的测试员工、测试模板和测试考核。不得删除共享数据库卷、真实模板、管理员账号、审计记录或历史签字材料。若无法区分测试数据，保留数据并提交人工清理清单。
