# Feature Specification: 荭杏业务初始化

**Created**: 2026-10-01
**Status**: Ready for implementation
**Input**: 初始化原表实际部门、岗位及每岗位模板，不再初始化张三、王五等演示账号。恢复本地管理员，日常验收统一使用 localhost。

## User Scenarios & Testing

### User Story 1 - 初次启动即有真实业务目录 (Priority: P1)

管理员首次部署后能看到原表九个部门及十八套月度岗位模板，无须逐项配置。

**Independent Test**: 空环境启动后检查全部部门、岗位、维度、指标、权重和评分类型，与原表一致，且没有演示员工和模拟评分。

**Acceptance Scenarios**:
1. **Given** 空业务目录，**When** 初始化，**Then** 创建九部门、十八个部门岗位条目、十八套已发布模板。
2. **Given** 原表内部权重不等于百分之百，**When** 初始化，**Then** 保留原值，逐项综合权重合计仍为百分之百。
3. **Given** 初始化失败，**When** 再次启动，**Then** 无半套数据且可以重试。

### User Story 2 - 更新不覆盖维护成果 (Priority: P1)

HR 修改、停用或删除初始模板后，更新系统不恢复旧配置或生成重复模板。

**Independent Test**: 连续初始化两次，修改和删除一个模板再初始化，确认修改及删除保留。

**Acceptance Scenarios**:
1. **Given** 已初始化，**When** 重启，**Then** 目录数量和维护内容不变。
2. **Given** 已有同名部门及同部门岗位周期模板，**When** 首次补齐目录，**Then** 复用已有数据，不改其状态、名称、内容或历史考核。
3. **Given** 已有员工，**When** 初始化，**Then** 不删除或改写员工，不创建张三等账号，即使保留旧演示开关。

### User Story 3 - 管理员及岗位可直接使用 (Priority: P2)

经明确授权恢复本地管理员，创建员工时按部门选择原表岗位，避免岗位名称猜测。

**Independent Test**: 本地管理员登录成功且拥有超级管理员权限，员工表单出现所选部门的岗位选项。

**Acceptance Scenarios**:
1. **Given** 本地不存在管理员，**When** 使用一次性凭据恢复，**Then** 创建 admin / yangwenzhe@howxing.com 并写审计；密码不纳入代码、镜像或公共响应。
2. **Given** 已有有效管理员，**When** 重复初始化，**Then** 密码及角色不改变。
3. **Given** 不同部门，**When** 创建或编辑员工，**Then** 岗位建议随部门更新，并保留自定义岗位输入。

### Edge Cases

- 原表更改不自动升级已初始化的数据，需另立显式升级任务。
- 重名部门造成歧义时拒绝初始化并给出名称，而非猜测关联。
- 缺少评分人账号不凭空生成账号或评分职责，创建考核仍沿用缺失职责校验。
- 原表分数和模拟验收数据不作为业务初始数据。
- 空岗位目录返回空列表；旧员工的非目录岗位仍可编辑。

## Requirements

### Functional Requirements

- **FR-001**: 首次初始化必须包含原表九部门及其负责人、工程师十八套月度模板，原始指标、维度、权重、评分指引和评分类型可追溯。
- **FR-002**: 必须遵守方案 A，不归一化权重，不把原表已填评分或测试评分当初始数据。
- **FR-003**: 初始化必须幂等、原子化；保留 HR 的修改、停用、删除和既有匹配模板，禁止改写历史。
- **FR-004**: 启动及业务初始化入口均不得创建演示员工、默认弱密码账号或开启公开注册；旧员工不自动删除。
- **FR-005**: 每个原表部门的两类岗位必须持久化，员工表单按部门提供岗位建议，同时允许自定义岗位。
- **FR-006**: 本地管理员恢复必须使用显式邮箱和文件凭据、保留已有管理员密码、记录审计且不得公开密码或哈希。
- **FR-007**: 岗位查询必须认证授权；不能包含员工或凭据数据，失败有明确反馈。
- **FR-008**: 普通环境不清库、不切换数据库、不重建隔离测试数据；最终给出 localhost 页面验收方法和初始化更新说明。

### Key Entities

- 部门：使用原表标题中的部门名称。
- 部门岗位：部门与岗位名称的唯一组合，区别于权限角色。
- 模板：部门、岗位及周期绑定，包含可维护的权重结构。
- 初始化记录：记录业务目录版本与来源，阻止重复或自动覆盖。

## Success Criteria

- **SC-001**: 初始业务目录与原表的九部门、十八岗位条目、十八模板逐项一致。
- **SC-002**: 重复启动、HR 修改和删除后的重启，新增重复条目及覆盖次数均为零。
- **SC-003**: 所有初始化入口创建演示员工和模拟考核的数量均为零。
- **SC-004**: 管理员能在 localhost 登录并在员工表单直接选择原表岗位。

## Assumptions

- 初始化目录默认启用，可显式关闭用于已有非荭杏部署及隔离验收。
- 十八模板校验通过后发布；评分职责需按实际员工配置，不创建虚构人员。
- 沿用目前产品团队负责人指标的 CTO 回退解析规则，并在指标说明保留原文，不新增职责引擎。
- 当前环境中的旧演示员工保留，不把“不再初始化”解释为删除已有数据。
- HR 项目工时、周期汇总、线上部署、完整岗位管理界面不属于本增量。
