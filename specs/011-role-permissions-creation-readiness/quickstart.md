# 验证方法

## 角色权限

1. 用户自行执行 `docker compose up -d --build`，使用原管理员账号访问正常本地地址（当前 http://localhost）。不需要 git pull，也不删除数据卷。
2. 用户角色 -> 项目经理 -> 编辑角色。名称和直属上级要求只读，权限/范围/说明可保存。
3. 取消一项可选权限并保存，再打开此角色确认；其他角色权限与绑定用户数量不变。
4. 对应角色用户刷新或重新登录，确认相关功能权限改变。
5. 重启后重新查看，确认取消的权限未恢复。测试后恢复原权限。
6. 超级管理员无编辑按钮；未授权用户无编辑入口，直接请求也403。

## 考核创建

1. 创建考核选择软件应用开发部工程师，模板匹配、已解析负责人和当前流程模式应可见。
2. audit 模式阻塞是部署开关，不是账号密码或角色问题。确认后将 `.env` 增加 `EVALUATION_WORKFLOW_MODE=enabled`，重建 backend；仅改文件不重建容器无效。
3. 在评分职责配置 PM/PRODUCT_MANAGER 的真实在职人员和公司/部门/岗位作用域（公司范围不可盲用）。系统角色授权不替代职责。
4. 返回创建弹窗重新选择员工，全部条件满足后创建，检查详情中各指标评分人、任务数量与模板一致。
5. 缺少职责仍应阻塞，不能产生半成品考核；历史任务不应改变。

## 自动验证

- Go: `go test ./...`（本次使用已存在的隔离 Go 测试容器，内存数据库）。
- Frontend: Node unit tests、tsc --noEmit、目标文件 lint、临时源码目录的 Next production build。
- 页面验收仅使用隔离克隆；不修改真实角色或评分职责；结束停止临时服务。
