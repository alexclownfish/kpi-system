# Feature Specification: 独立角色权限维护与考核创建准备

**Feature Branch**: 当前工作分支（不切换已有修改）
**Created**: 2026-10-02
**Status**: Ready
**Input**: 仍无法创建考核；无法单独修改角色权限。

## User Scenarios & Testing

### User Story 1 - 单独维护角色权限 (Priority: P1)

管理员可直接编辑普通系统角色与自定义角色的权限，不必复制角色或重新分配员工。
**Why this priority**: 现有系统角色完全只读，无法按实际职责调整。
**Independent Test**: 修改项目经理角色的一项权限，验证该角色用户更新、其他角色不变，重启后保留。
**Acceptance Scenarios**:
1. **Given** 有角色编辑权限及足够授权范围，**When** 修改普通系统角色，**Then** 仅此角色的权限与范围改变，用户绑定与系统身份不变。
2. **Given** 无角色编辑权限或目标权限超过自身，**When** 请求编辑，**Then** 被拒绝且原记录完整保留。
3. **Given** 超级管理员角色，**When** 试图修改权限，**Then** 明确拒绝，保留系统恢复入口。
4. **Given** 已自定义的系统角色，**When** 重启服务，**Then** 不补回删除的权限，不恢复旧数据范围。

### User Story 2 - 明确考核创建前置条件 (Priority: P1)

HR 从创建预览获得明确的流程模式与缺失评分职责信息，并能进入评分职责维护；补齐条件后新考核按模板生成任务。
**Why this priority**: 模板已匹配，但安全开关与缺失职责阻塞创建，不能靠授予角色自动猜测评分人。
**Independent Test**: 审计模式预览不可创建；启用模式缺少评分人仍不可创建；补齐职责后创建成功，任务与模板一致。
**Acceptance Scenarios**:
1. **Given** 审计模式，**When** 预览新版模板，**Then** 明确报告未启用，不写入任何考核。
2. **Given** 缺少项目经理或产品经理评分职责，**When** 预览，**Then** 保留已匹配模板与已解析评分人并给出职责维护入口。
3. **Given** 已启用且全部职责可解析，**When** 创建考核，**Then** 保存评分任务、模板快照，绝不自动改写历史考核。

### Edge Cases

- 普通系统角色名称、角色代码、直属上级要求保持稳定；编辑请求改变这些属性时拒绝。
- 空权限集可以保存，重启不补回；选择写权限按现有规则补充查看权限。
- 权限目录新增仍存在，但管理员定制角色不自动获得新权限；超级管理员继续使用完整默认权限。
- 普通系统角色仍不可删除；越权修改高权限角色也拒绝。
- 没有职责查看权限的用户看不到维护入口；错误内容必须为可显示的文本。

## Requirements

### Functional Requirements

- **FR-001**: 允许独立编辑普通系统角色和自定义角色，保留用户绑定和角色身份。
- **FR-002**: 强制角色编辑授权、目标及授予权限上限和数据范围；拒绝超级管理员角色编辑；角色维护授权边界校验的拒绝与保存成功写入审计。
- **FR-003**: 重启保留已保存的普通系统角色权限及数据范围，包括空权限集。
- **FR-004**: 系统角色稳定属性不可编辑、不可删除；自定义角色现有编辑能力不变。
- **FR-005**: 创建预览报告流程模式与业务职责阻塞，并提供权限感知的职责维护入口；不绕过缺失评分人。
- **FR-006**: 只有流程已启用且职责完整才能创建新版考核，创建结果保留模板快照和任务一致性。
- **FR-007**: 写操作显示提交中、成功与失败；不自动改写实际人员职责、环境开关、历史考核或密码。

### Key Entities

- 角色：稳定身份、用户绑定、权限、数据范围、管理员已定制状态。
- 创建准备：匹配模板、运行模式、已解析评分人、阻塞原因。
- 评分职责：业务类型、人员与作用域，独立于登录角色。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 普通系统角色可直接保存权限，修改一个角色时其他角色及所有用户绑定零变化。
- **SC-002**: 允许、拒绝、重启保留、空权限、超级管理员保护场景全部通过回归验证。
- **SC-003**: 审计阻塞、缺少职责阻塞、配置齐全后创建三个场景结果一致，无部分考核残留。

## Assumptions

- 开放角色配置能力不意味着自动授予现有角色额外权限。
- 不猜测真实业务人员绑定；本地职责和模式变更需用户确认，可先使用隔离测试数据验收代码。
- 本次不开放超级管理员权限定制；不引入第二套评分流程。
- 无需进一步澄清代码实现范围；实际环境配置授权单独等待用户答复。
