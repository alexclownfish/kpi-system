# Feature Specification: 绩效计算引擎与模板维护

**Feature Branch**: `main`
**Created**: 2026-09-26
**Status**: Proposed MVP

## Clarifications

### Session 2026-09-26

- Q: 总分如何计算？ → A: 严格按照附件模板的维度占比、维度内权重、指标得分计算综合权重和加权得分后汇总。
- Q: 评分人如何确定？ → A: 按岗位自动匹配模板定义的评分人类型，并解析为实际组织成员；管理员可在本次考核中调整具体人员。
- Q: 何时可以进入员工确认？ → A: 所有必填指标均已完成有效评分后才允许进入待确认。
- Q: HR 是否持续维护模板？ → A: 允许 HR 持续维护模板，但已创建考核必须保存模板快照，不受后续模板修改影响。
- Q: 投入占比如何参与汇总？ → A: 采用附件现有规则：项目投入占比低于 20% 时该项目加权贡献按 0 计；20% 及以上按总分乘有效投入占比计算，阈值应为可配置规则。

### Session 2026-10-01

- Q: 原表部分负责人模板维度内权重不等于 100%，如何处理？ → A: 采用 A，保留原表数值，以逐项四舍五入后的综合权重合计 100% 为保存、发布和计算校验标准；不要求维度内指标权重合计 100%，不归一化。

## User Scenarios & Testing

### User Story 1 - 维护岗位考核模板 (Priority: P1)

HR 可以为部门和岗位维护月度、季度或年度考核模板，配置考核维度、指标、权重、评分标准、数据来源和评分人类型。

**Independent Test**: HR 按原表录入模板，综合权重合计 100% 时可保存和发布，即使维度内权重合计为 73%、80%、120% 或 140%；综合权重合计不为 100% 时拒绝保存和发布。

### User Story 2 - 按岗位创建考核 (Priority: P1)

创建考核时，系统根据被考核人的部门、岗位类型和考核周期自动匹配有效模板，并生成当时的模板和评分人配置快照。

**Independent Test**: 为两个岗位配置不同模板，分别创建考核，验证指标、权重和评分任务按岗位模板生成。

### User Story 3 - 完成评分并计算总分 (Priority: P1)

评分人完成被分配的指标评分后，系统按照模板权重计算指标加权分、总分和等级。多人评分指标按照模板配置的聚合方式计算，MVP 默认使用平均分。

**Independent Test**: 输入附件中的示例权重和分数，系统计算出与表格一致的总分；存在必填指标未评分时，不允许进入员工确认。

### User Story 4 - HR 持续维护与历史冻结 (Priority: P1)

HR 可以停用、复制和维护模板。模板变更不影响已经创建的考核；历史考核按照创建时快照继续计算和导出。

**Independent Test**: 修改模板权重后，新建考核使用新规则，旧考核仍使用旧规则并可重复导出相同结果。

### User Story 5 - 月度、季度和年度汇总 (Priority: P2)

HR 可以查看项目投入占比、项目加权贡献、周期总分、年度总分和等级。系统同时保留精确分数和等级。

**Independent Test**: 同一员工参与多个项目时，投入占比低于 20% 的项目贡献为 0，其余项目按总分乘投入占比计算并汇总。

## Functional Requirements

- **FR-001**: 模板 MUST 支持考核维度、维度占比、指标、维度内权重和自动计算的综合权重。
- **FR-002**: 指标综合权重 MUST 按“维度占比 × 维度内权重 ÷ 100”四舍五入至 1 位小数后计算，保存、发布和计算前所有有效指标的综合权重合计必须为 100%。各权重须为 0–100 的有限数值，每个维度须有指标；不得额外要求维度内指标权重合计 100%，不得归一化或修改原表权重。维度合计仅供展示。
- **FR-003**: 指标评分 MUST 使用 0–100 分范围，并保存评分标准、数据来源和评分说明。
- **FR-004**: 模板 MUST 按部门、岗位类型和考核周期匹配；岗位自动选择有效模板，不能依赖固定系统角色名称。
- **FR-005**: 模板 MUST 配置评分人类型；创建考核时系统按组织关系解析为实际用户，并允许有权限的管理员调整本次考核评分人。
- **FR-006**: 一个指标可以配置一个或多个评分人；多人评分时 MVP 默认取有效评分的算术平均，并记录每个评分人的原始评分。
- **FR-007**: 系统 MUST 区分未评分、有效 0 分和不适用；所有必填指标未完成有效评分时，考核不得进入待确认状态。
- **FR-008**: 总分 MUST 等于所有指标最终得分乘综合权重后的加权得分之和；等级按 S/A/B/C/D 阈值自动计算。
- **FR-009**: 创建考核时 MUST 保存模板、指标、权重、评分人配置和计算规则快照；后续模板修改不得影响已创建考核。
- **FR-010**: HR MUST 能持续维护模板，包括复制、编辑、停用和发布新版本；已被历史考核使用的模板版本不得被破坏性覆盖。
- **FR-011**: 项目汇总 MUST 按附件规则计算有效投入占比：低于 20% 时加权贡献为 0，达到阈值时按总分乘投入占比计算；阈值必须可配置。
- **FR-012**: 月度、季度和年度汇总 MUST 同时保存数值总分和等级，并保留周期权重及计算版本。
- **FR-013**: 所有权重变更、模板发布、评分提交、总分计算、进入确认和汇总操作 MUST 记录审计信息。
- **FR-014**: 模板维护和评分界面 MUST 提供加载中、成功、失败、权重不合法、评分未完成等明确反馈。
- **FR-015**: MVP MUST 不支持任意 Excel 公式、宏、脚本或自由公式执行；Excel 仅用于受控模板初始化和后续结构化维护。

## Edge Cases

- 逐项舍入后的综合权重合计不为 100% 时不能保存或发布模板；不能用未舍入合计替代校验。
- 指标没有评分人、评分人账号停用或组织关系无法解析时，考核不能进入评分阶段，并显示具体缺失项。
- 未评分不能自动变成 0 分，也不能自动判定为 D。
- 已进入待确认或已完成的考核不能因模板修改而重新套用新权重。
- 同一指标重复评分时按评分任务去重，不能重复计入总分。
- 模板停用后不能创建新考核，但历史考核仍可查看、确认和导出。
- 已完成考核的总分、等级和快照不可由普通编辑接口修改。

## Success Criteria

- **SC-001**: 附件中 9 个部门模板的权重结构可完整录入，发布校验准确率达到 100%。
- **SC-002**: 使用同一组权重和分数时，系统总分与附件公式结果一致率达到 100%。
- **SC-003**: 存在任一必填指标未评分时，100% 的确认请求被拒绝且不改变考核状态。
- **SC-004**: 模板修改后，旧考核重复计算和导出的字段、权重、总分与修改前保持一致。
- **SC-005**: HR 可在 3 分钟内复制一个模板、修改权重和指标并发布新版本。
- **SC-006**: 一人多项目汇总时，投入占比低于 20% 的项目贡献 100% 按规则归零，其他项目计算结果与附件一致。

## Assumptions

- 评分人类型 PM、部门负责人、产品经理、CTO 是业务职责类型，不直接等同于 RBAC 角色。
- MVP 的自动匹配来源为部门、岗位类型、直属上级和组织关系；复杂外部系统数据接入不在本 Feature 内。
- 评分标准先由评分人依据模板人工给出 0–100 分，后续再增加项目计划、缺陷、测试等数据源自动换算。
- 导出文件继续由 `005-unified-result-exports` 负责，使用本 Feature 产生的最终结果和快照。
