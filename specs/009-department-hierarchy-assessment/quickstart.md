# Localhost Acceptance
1. 用户执行 docker compose up -d --build，不git pull、不down -v、不切换数据库。
2. 部门管理确认机器人事业研发部及四子部门；编辑父部门并保存，禁止循环/删除仍有子部门的父部门。
3. 员工管理的软件应用开发工程师保留原岗位；创建考核预览应匹配软件应用开发部工程师模板，显示具体缺失职责而非“无法匹配”或白屏。
4. 为真实上级维护机器人事业研发部DEPARTMENT_MANAGER或公司CTO职责；子部门负责人编辑直属上级时可选这些账号。工程师上级仍同部门。
5. 缺少PM/产品/部门负责人职责时明确显示，不为真实业务自动造人。模板要求的每种职责维护后创建；若EVALUATION_WORKFLOW_MODE禁写则提示开关，需管理员原部署策略允许enabled才创建。
6. 创建负责人考核，提交自评，确认待评分任务给上级而非自己；历史快照不改变。
7. 测试数据全部在内存SQLite/临时测试实例，普通库不生成测试考核。

## 当前普通环境的两个前置条件
- 当前为audit模式。`.env`中仅将 `EVALUATION_WORKFLOW_MODE=enabled` 设为启用后再重建，才能创建weighted-v2考核；此次没有擅自改变部署策略。保留JWT、端口、管理员等其它配置。
- 评分职责不是权限角色：需要确认CTO朱亮、PM邹风华、产品经理郭庆，以及嵌入式负责人毛一凡、软件应用负责人王成斌的真实职责。未确认前不写入普通库。其余两个子部门同样需真实负责人；无需虚构账号。
- 负责人可明确指定合法上级，也可保持空值由最近上级部门负责人职责、再公司CTO自动解析。多个候选会要求明确指定，不随机选。
- 历史考核不会自动换评分人；本次新创建的考核使用新规则。
- 测试结果与隔离页面证据见 `acceptance.md`。临时18096/18097不是日常访问地址。
