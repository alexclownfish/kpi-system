# Research: 生产 PostgreSQL 迁移

## 决策

| 议题 | 决策 | 原因 |
| --- | --- | --- |
| 数据库驱动 | DB_DRIVER=postgres 显式启用；未配置继续 SQLite | 保持开发兼容，防止 PG 故障时静默读错库 |
| 凭据 | PG 管理员与应用角色各使用不同的只读口令文件；管理员目录不挂后端 | 避免 Compose 配置和进程参数暴露密码，并限制日常后端权限 |
| 目标 schema | 用现有 GORM AutoMigrate 的 schema-only 命令创建 | 正常启动会 seed 和修复业务数据，迁移前不应执行 |
| 数据迁移 | 本次使用 `--scope identity`，显式白名单九表；原 `--scope full` 保留但不执行 | 用户修订为只保留账号、组织、RBAC；不能以“全量”报告冒充 |
| 目标业务表 | `init-schema` 创建全部结构，九表复制记录；普通后端首启前其余表零记录 | 不依赖旧模板/考核；之后新生设置/审计不算旧数据 |
| 附件归档 | 旧签字卷全量封存、计算哈希并异机保存；不复制到新签字卷 | 旧签字元数据不迁，新库无可引用的旧附件；归档为回退来源 |
| 备份 | PostgreSQL 用 pg_dump -Fc + 签字目录归档；恢复用隔离库 pg_restore | 现有页面 SQL 备份/恢复为 SQLite 特定实现 |
| 切换 | 新旧 Compose 不共享数据库卷；切网关前冻结旧写入 | 回退不依赖反向数据库迁移 |

## 已知风险与停机条件

- 源库仍有写入或 SQLite 副本不一致：停止迁移，重新获取一致性快照。
- 九张范围内源表/字段没有目标对应结构：停止，不能丢弃任何范围内的字段；被排除表不参与本次匹配，但在完整旧库归档保留。
- 九表源端外键、约束、类型、时区、主键序列或行数核对失败：事务回滚，不启动后端。被排除表的历史孤儿外键不应误拦身份迁移。
- 没有有效 `super_admin`、九表角色/数据范围绑定不符或普通后端首启前目标任何非九表已有记录：停止创建放行标记。
- 仅有应用页面导出的旧 SQL 文件而没有完整 SQLite 数据库：不足以作为旧库全量归档，也不能安全执行九表迁移。
- 旧生产卷、实际网关上游、附件路径尚待在服务器只读核验；任何示例卷名都不得盲目用于生产写操作。
- 用户贴出的生产 JWT 密钥已暴露；上线前本机轮换，不打印新值，所有持旧令牌的会话需重新登录。
- `SEED_HONGXING_CATALOG=false` 使目标模板为空，用户若要发起新考核须另行配置或初始化模板；不能在身份迁移验收中承诺新考核立即可用。
