# Research: 生产 PostgreSQL 迁移

## 决策

| 议题 | 决策 | 原因 |
| --- | --- | --- |
| 数据库驱动 | DB_DRIVER=postgres 显式启用；未配置继续 SQLite | 保持开发兼容，防止 PG 故障时静默读错库 |
| 凭据 | PG 管理员与应用角色各使用不同的只读口令文件；管理员目录不挂后端 | 避免 Compose 配置和进程参数暴露密码，并限制日常后端权限 |
| 目标 schema | 用现有 GORM AutoMigrate 的 schema-only 命令创建 | 正常启动会 seed 和修复业务数据，迁移前不应执行 |
| 数据迁移 | 读取一致性 SQLite 文件副本，枚举全部非系统表，按目标 schema 写入并保留 ID | 旧页面 SQL 备份只含旧表子集，不能用来迁移 |
| 附件迁移 | 单独复制签字卷，文件数量及全部文件哈希核对 | 数据库只存元数据，文件不在 SQLite 内 |
| 备份 | PostgreSQL 用 pg_dump -Fc + 签字目录归档；恢复用隔离库 pg_restore | 现有页面 SQL 备份/恢复为 SQLite 特定实现 |
| 切换 | 新旧 Compose 不共享数据库卷；切网关前冻结旧写入 | 回退不依赖反向数据库迁移 |

## 已知风险与停机条件

- 源库仍有写入或 SQLite 副本不一致：停止迁移，重新获取一致性快照。
- 源库出现目标 schema 不识别的业务表或字段：停止，不丢弃表/字段；先补目标结构或明确迁移规则。
- 迁移时约束、类型、时区、主键序列或行数核对失败：事务回滚，不启动后端。
- 仅有应用页面导出的旧 SQL 文件而没有完整 SQLite 数据库：不足以证明全量迁移。
- 旧生产卷、实际网关上游、附件路径尚待在服务器只读核验；任何示例卷名都不得盲目用于生产写操作。
