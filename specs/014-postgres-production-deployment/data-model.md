# Data Model: 迁移边界与不变量

此次不重新设计业务表。目标 PostgreSQL schema 由当前模型创建；源端以 sqlite_master 枚举所有非内部表，目标端按表/列集合匹配，不允许静默忽略源表或源列。员工、角色及授权、部门与岗位、模板和指标、考核/评分/确认、快照、导入、审计、设置均是迁移范围，不能依赖旧备份的固定名单。

| 实体 | 关键不变量 | 验收 |
| --- | --- | --- |
| 业务表行 | ID 与字段值保留，源表没有缺失 | 逐表行数相等；抽样主键字段对比 |
| 关联 | 角色授权、评分人与考核、签字与考核等外键保持 | 目标库 FK 检查无错误；关键业务关系抽样 |
| 序列 | PostgreSQL 自增值不小于现有最大 ID | 新增一条隔离测试记录不撞主键；迁移工具检查序列 |
| 身份信息 | 邮箱、密码哈希、启用状态、角色保持 | 原账号登录；权限允许/拒绝各验收一次 |
| 附件 | 硬盘文件与签字元数据对应 | 文件总数/字节数及抽样哈希；页面访问历史文件 |
| 回退基线 | SQLite 与附件的只读快照、旧服务配置保存 | 在隔离目录能恢复，切流前不删旧卷 |

迁移事务应在目标全新空库执行。迁移前后的生产写入必须被冻结，避免两库分叉；回退到旧库之后，不能把新库中新产生的记录自动视为已同步。
