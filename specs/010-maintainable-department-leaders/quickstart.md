# Local Acceptance
1. 用户在本项目执行docker compose up -d --build；无需git pull，不down -v、不修改密码或切换数据库。
2. 部门管理编辑“机器人事业研发部”，设置该部门真实在职负责人。若该员工尚在其它部门，先在员工管理调整其实际所属部门；系统不猜测人选。
3. 编辑“软件应用开发部”，上级部门选择“机器人事业研发部”，部门负责人选择王成斌，保存。其它子部门同理，可自行改层级或清空。
4. 员工管理编辑王成斌，直属上级应包含上步父部门负责人；保存、刷新确认。无需另建DEPARTMENT_MANAGER评分职责。
5. 创建新的负责人考核：预览部门负责人评分人是合法显式上级；未指定时使用最近父负责人。工程师该评分人为本部门明确负责人。
6. 错误父关系/跨部门负责人/停用负责人/循环应拒绝并提示。历史考核不改；新流程开关、PM/产品/CTO其它职责仍遵守既有配置。
7. 自动化：server目录go test ./...，前端unit/tsc/build。全部业务测试在内存库或隔离副本，普通库不写测试数据。

注意：模板中的“部门负责人/直属上级”评分项使用组织上级；单独指定CTO、PM、产品经理的项目仍遵循原模板职责，不因员工上级设置自动替换。测试结果见 `acceptance.md`。
