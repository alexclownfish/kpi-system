# Feature Specification: 批量结果处理与签字回收

**Feature Branch**: `main`
**Created**: 2026-09-17
**Status**: Approved for implementation

## User Scenarios & Testing

### User Story 1 - 批量导出签字表 (P1)

HR 按部门、周期和确认状态筛选考核，一次下载 ZIP；每名员工一份可直接 A4 打印的正式 PDF，并附汇总表。

**Independent Test**: ZIP 中每条可见且已定稿考核各有一份 PDF，PDF 展示版本、校验码和签字栏，跨数据范围记录不出现。

### User Story 2 - 批量导入最终评分 (P1)

HR 下载带稳定编号的 Excel 模板，填写最终分与评价后上传预检；系统逐行反馈错误，并允许仅提交完全有效的考核。

**Independent Test**: 工作簿同时含有效、越界、重复和已完成记录时，预检准确分类；提交后只更新完全有效的考核并重算总分。

### User Story 3 - 查看签字回收统计 (P2)

HR 查看待确认、在线确认、纸质确认、未回收及回收率，并查看员工明细。

**Independent Test**: 在线、纸质和未确认三类记录的汇总与明细一致，且受数据范围约束。

## Requirements

- **FR-001**: 批量导出 MUST 支持部门、年度、月度/季度/年度和确认状态筛选。
- **FR-002**: 批量导出 MUST 仅包含调用人数据范围内 `pending_confirm` 或 `completed` 的考核。
- **FR-003**: ZIP MUST 为每条考核包含一份正式 PDF，并包含一份 XLSX 汇总表。
- **FR-004**: PDF MUST 包含逐项最终分、总分、评价、结果版本、校验码和签字栏。
- **FR-005**: 模板 MUST 包含考核 ID、评分项 ID、员工、部门、周期、指标、满分、当前最终分、导入最终分和最终评价。
- **FR-006**: 预检 MUST 校验文件、权限、数据范围、状态、所属关系、重复行和分数范围，并返回逐行结果。
- **FR-007**: 提交 MUST 以考核为原子单位，仅更新完全有效且预检后未变化的考核，并重算总分。
- **FR-008**: 已确认或已完成考核 MUST 禁止导入修改。
- **FR-009**: 导入批次 MUST 持久化预检内容、创建人、有效期、状态和提交摘要。
- **FR-010**: 签字回收统计 MUST 返回汇总、回收率和员工级明细，应用相同筛选与数据范围。
- **FR-011**: 所有写操作 MUST 显示进行中、成功和可操作的失败反馈。

## Edge Cases

- 无符合记录时不生成空 ZIP；PDF 失败时不返回残缺 ZIP并清理临时文件。
- 只接受最大 10 MB 的 `.xlsx`；空文件、缺列和损坏文件明确报错。
- 同一评分项重复、错配、分数越界均为错误；同一考核有任一错误则整体不可提交。
- 批次 30 分钟过期；预检后考核状态或更新时间改变时提交拒绝该考核。

## Success Criteria

- **SC-001**: HR 可在 3 分钟内完成一个部门一个周期的签字表下载。
- **SC-002**: 预检对重复、越界、越权、已完成和错配行识别率为 100%。
- **SC-003**: 部分提交不修改存在错误的考核，有效考核内不存在半更新。
- **SC-004**: 签字统计汇总与明细数量一致，回收率计算误差为 0。

## Clarifications

- PDF 使用后端 Chromium HTML-to-PDF；预检批次默认 30 分钟有效。
- “仅提交有效数据”以考核为粒度；导入对象限定为 `pending_confirm`。
