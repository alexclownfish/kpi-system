# Feature Specification: 跨部门兼任负责人

**Created**: 2026-10-28
**Status**: Implementation and automated validation complete; deployment acceptance pending
**Input**: 用户确认落地一个账号（如 CTO）兼任明确指定的多个部门负责人，普通员工可直接选择其为上级。

## User Scenarios & Testing

### US1 - 明确任命兼任负责人 (P1)
管理员在创建或编辑部门时选择已有在职用户，可为两个部门选择同一 CTO，账号所属部门、岗位、角色保持不变。编辑列表正确显示跨部门负责人。
**Independent Test**: 同一总部用户担任两个子部门负责人；停用/不可见人员不能被任命，未授权者写入被拒。

### US2 - 创建员工和按模板评分 (P1)
员工保留真实所属部门，直属上级可选本部门在职用户或明确任命的跨部门负责人，无需伪造部门负责人账号。模板的部门负责人指标匹配实际任命人员，CTO 指标仍使用独立评分职责。同一用户的不同评分职责、指标和权重保持独立。
**Independent Test**: 两部门员工分别创建考核且评分人相同；无任命的跨部门人员、本人评分、循环上级拒绝；更换负责人不修改已有任务和快照。

### US3 - 受控可见范围与交接 (P1)
具备部门数据范围及功能权限的兼任负责人可以查看所属及负责部门的数据；部门树范围包含这些部门的子部门。SELF、直属下属、ASSIGNED 原有语义不自动扩大；任命不赋予新权限或全公司范围。更换负责人提示仍指向旧负责人的员工数量，不静默修改直属上级。
**Independent Test**: DEPARTMENT/DEPARTMENT_TREE 正确覆盖两个负责部门且排除无关部门；SELF 不扩权；变更任命立即收回组织范围但保留已有评分任务授权。

### Edge Cases
- 负责人停用时解析失败，不悄悄选择其他用户；调动所属部门不使兼任失效。
- 部门层级和上级链不能成环；同一用户兼任父子部门时本人考核不能选择自己评分。
- 清空或更换负责人只改变未来匹配；已有员工的上级与已有任务保留，明确提示交接。

## Requirements
- FR-001 MUST 支持一人负责多个部门且保留单一所属部门/岗位/角色。
- FR-002 MUST 在新建和编辑部门时选择已有在职、授权范围内人员，正确显示其姓名；未授权/停用人员拒绝。
- FR-003 MUST 允许普通员工选择明确任命的跨部门负责人作为上级，禁止任意跨部门人员、本人和循环关系。
- FR-004 MUST 按模板职责匹配评分人、保留不同职责任务及权重；既有考核任务/快照不得因组织调整改变。
- FR-005 MUST 按部门/部门树数据范围合并本人所属与明确负责的部门，保留其他范围语义，功能权限独立。
- FR-006 MUST 提示更换/清空负责人后的旧上级关联数量，保留员工字段并记录审计；不自动迁移员工关系。
- FR-007 MUST 不依赖 CTO 角色名自动任命，不创建重复账号，不清理生产数据。

## Key Entities
部门、员工、部门负责人任命、直属上级关系、角色权限/数据范围、评分职责、考核任务和历史快照。

## Success Criteria
1. 一个总部账号兼任两个业务部门负责人后，两部门都能创建员工、匹配模板和正确生成评分任务。
2. 越权、停用负责人、无关跨部门上级、自评/循环负例全部拒绝。
3. 更换负责人后旧考核快照和任务不变，原员工上级不被改写；新考核使用新负责人。
4. 受管与无关部门数据的允许/拒绝自动化测试通过，页面可独立验收。

## Assumptions
已确认方案作为范围，无需再澄清；现有负责人替换不批量改上级，先提示并由员工编辑处理；不实现代理有效期、多负责人并行或自动全公司任命。
