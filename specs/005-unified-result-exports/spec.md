# Feature Specification: 统一绩效结果导出

**Feature Branch**: `main`

**Created**: 2026-09-18

**Status**: Draft

**Input**: User description: "统一考核详情最终评分表与批量签字 PDF；按考核模板配置不同岗位所需内容，并支持可控的自定义表格导出。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 单个与批量导出保持一致 (Priority: P1)

有报表导出权限的用户对同一份已定稿考核执行单个导出或批量签字表导出时，看到相同的基本信息、评分字段、总结内容和签字栏，不再因入口不同得到两种业务口径。

**Why this priority**: 当前两条导出链路内容不一致，会直接导致纸质签字材料与详情留档不一致。

**Independent Test**: 选择同一份已定稿考核，分别导出 Excel、单份 PDF 和批量 PDF，逐项核对标题、列顺序、评分值、总结与签字栏。

**Acceptance Scenarios**:

1. **Given** 同一考核已定稿且模板使用“最终签字简版”，**When** 用户分别执行单个和批量导出，**Then** 两种入口的业务字段、顺序和签字栏一致。
2. **Given** 考核仍未定稿，**When** 用户尝试导出签字材料，**Then** 系统拒绝导出并明确提示最终结果尚未定稿。
3. **Given** 用户没有报表导出权限或不在考核数据范围内，**When** 用户请求导出，**Then** 系统拒绝并不泄露考核内容。

---

### User Story 2 - 按考核模板配置导出版式 (Priority: P1)

绩效管理员可在考核模板中选择系统预设或配置结果导出的标题、评分列、总结区和签字栏，使不同岗位使用的不同考核模板能输出适合各自业务的签字表。

**Why this priority**: 岗位差异应通过考核模板表达，避免在岗位和导出代码中重复维护规则。

**Independent Test**: 为两个模板设置不同的列和签字栏，分别创建并定稿考核，验证每份结果按其模板配置导出。

**Acceptance Scenarios**:

1. **Given** 管理员编辑一个模板，**When** 选择字段、调整顺序并保存，**Then** 再次打开模板时配置完整保留并能预览其含义。
2. **Given** 两个岗位选用了不同模板，且模板导出配置不同，**When** 分别导出考核结果，**Then** 输出内容随模板配置不同而不同。
3. **Given** 旧模板没有自定义配置，**When** 导出结果，**Then** 系统自动使用“最终签字简版”，无需人工迁移。
4. **Given** 配置缺少必需字段或含不支持的字段，**When** 管理员保存，**Then** 系统拒绝并说明需要修正的内容。

---

### User Story 3 - 冻结历史导出版式 (Priority: P2)

考核结果完成员工确认或纸质签字归档后，系统将当时使用的导出版式与结果一并冻结；即使管理员之后修改模板，历史签字表仍可按原版本重复导出。处于待确认状态且尚未完成签字的考核，重新导出时应采用模板的最新已保存版式并生成新的结果版本。

**Why this priority**: 纸质签字、审计和争议处理需要同一结果版本始终可复现。

**Independent Test**: 定稿并导出一份考核，修改模板导出配置后再次导出该考核，验证旧考核仍使用原布局，而新定稿考核使用新布局。

**Acceptance Scenarios**:

1. **Given** 已完成确认的考核已有结果快照，**When** 模板配置后来发生变化，**Then** 重新导出仍使用快照中的旧版式。
2. **Given** 一个旧快照不包含版式信息，**When** 再次导出，**Then** 系统使用兼容的“最终签字简版”并保持结果可导出。
3. **Given** 待确认考核曾经导出过旧版式，**When** 管理员保存新的模板版式后再次导出，**Then** 系统使用新字段配置并生成新的结果版本。

---

### User Story 4 - 选择单份导出格式 (Priority: P2)

有权限的用户可从考核详情选择 Excel 或 PDF；两种文件适合电子留档或直接打印，但表达相同的业务字段。

**Why this priority**: 单份 PDF 可与批量打印流程一致，Excel 则保留日常复核和归档便利。

**Independent Test**: 对同一考核导出 Excel 与 PDF，验证字段集合、顺序、数值和签字栏一致，且两个文件均可正常打开。

**Acceptance Scenarios**:

1. **Given** 用户查看一份已定稿考核，**When** 选择 Excel 或 PDF，**Then** 系统生成对应格式并显示成功或失败反馈。
2. **Given** 导出生成失败，**When** 用户执行导出，**Then** 页面显示可理解的失败原因而不是静默无响应。

### Edge Cases

- 模板配置中所有可选评分列均被取消时，必须保留“指标”和“最终得分”两个核心列。
- 自定义标题为空、过长或签字栏名称重复时，系统应规范化默认值或拒绝保存并说明原因。
- KPI 项目较多、说明文字较长时，Excel 和 PDF 应自动换行并允许分页，不能截断核心得分数据。
- 批量导出包含多个不同模板时，每份 PDF 使用各自被冻结版式，汇总表继续保持统一汇总字段。
- 历史快照、旧模板或部分字段为空时，导出应提供兼容默认值，不能因缺少新字段而失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 让单个结果导出和批量签字 PDF 使用同一套导出字段定义与顺序规则。
- **FR-002**: 系统 MUST 以考核模板作为导出版式的配置归属；岗位只通过所选择的默认或实际考核模板间接影响导出内容。
- **FR-003**: 具备 KPI 编辑权限的用户 MUST 能配置导出标题、评分列及其顺序、总结区可见性和签字栏。
- **FR-004**: 系统 MUST 提供“最终签字简版”和“评分过程完整版”两个预设，并允许在预设基础上调整受支持字段。
- **FR-005**: 配置 MUST 至少包含指标名称和最终得分；评分列只能来自系统明确支持的字段目录。
- **FR-006**: 未配置版式的现有模板 MUST 自动使用“最终签字简版”。
- **FR-007**: 单份结果 MUST 支持 Excel 和 PDF 两种格式，且两种格式表达相同的字段、顺序、总结与签字栏。
- **FR-008**: 批量签字导出 MUST 为每份考核使用其自身模板或结果快照中的版式，并继续生成签字回收汇总表。
- **FR-009**: 系统 MUST 在结果快照中保存定稿时的导出版式，使历史结果不受后续模板修改影响。
- **FR-009A**: `pending_confirm` 且尚未完成确认的考核 MUST 在模板版式变化后使用最新已保存版式生成新快照；`completed` 考核 MUST 继续使用完成确认时的已有快照。
- **FR-010**: 对不含版式信息的历史快照，系统 MUST 使用兼容默认版式完成导出。
- **FR-011**: 所有导出请求 MUST 同时执行报表导出权限和考核数据范围校验，不能依赖前端隐藏按钮。
- **FR-012**: 模板版式保存与导出操作 MUST 向用户显示提交中、成功和失败状态。
- **FR-013**: 模板版式变更和导出操作 MUST 记录可追溯的审计信息。
- **FR-014**: MVP MUST 使用字段选择、顺序、标题、区域开关和签字栏配置，不包含任意单元格拖拽、自由公式、宏或用户上传可执行模板。

### Key Entities

- **结果导出版式**: 属于考核模板的受控配置，包含版式版本、标题、列定义、总结区和签字栏。
- **导出字段目录**: 系统支持的固定字段集合，定义字段标识、显示名称、适用区域和是否必需。
- **考核结果快照**: 已定稿考核的不可变结果版本，包含评分数据以及当时的导出版式副本。
- **导出文档**: 由同一结果快照和版式生成的 Excel 或 PDF 文件。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对同一考核，Excel、单份 PDF 与批量 PDF 的已配置业务字段及顺序核对一致率达到 100%。
- **SC-002**: 管理员可在 3 分钟内从任一系统预设完成一次模板导出版式调整并保存。
- **SC-003**: 100% 的旧模板和旧结果快照无需手工迁移即可继续导出。
- **SC-004**: 模板修改后，历史已定稿考核重复导出的版式与修改前保持一致率达到 100%。
- **SC-004A**: 模板保存新字段后，尚未确认的考核再次导出使用新字段的成功率达到 100%。
- **SC-005**: 对包含 100 个考核的批量导出，所有文件均使用各自正确模板版式，且没有跨模板串用字段的情况。
- **SC-006**: 所有导出和版式保存失败均在页面上给出可操作反馈，不出现静默失败。

## Assumptions

- 岗位与考核模板的选择关系沿用现有考核创建流程，本 Feature 不新增岗位直接绑定导出版式。
- MVP 的“自定义表格”是受控字段配置，不提供类似电子表格的任意单元格设计能力。
- 批量 ZIP 中的签字回收汇总表仍使用固定汇总列，因为它服务于回收管理而不是单份签字内容。
- 已定稿结果的评分数据继续由现有结果快照保证不可变；本 Feature 将版式一并纳入快照。
- 系统现有字体和 Chromium PDF 生成能力继续作为部署前提。
