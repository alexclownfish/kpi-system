# Feature Specification: 绩效结果打印签字与归档

**Feature Branch**: `main`

**Created**: 2026-09-17

**Status**: Approved for implementation

**Input**: 为最终绩效考核提供可打印的评分表，并支持在线确认或纸质签字材料回录归档。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 导出最终评分表 (Priority: P1)

HR 在考核进入待确认或已完成状态后，可以从考核详情导出适合 A4 打印的最终评分表，让员工线下签字。

**Why this priority**: 没有稳定的打印结果就无法形成纸质签字闭环。

**Independent Test**: 对一条待确认考核执行导出，所得表格包含员工、周期、最终指标得分、总分、总结、版本及签字栏，并可在一份连续打印文档中阅读。

**Acceptance Scenarios**:

1. **Given** 考核处于待确认状态且用户有导出权限及数据范围，**When** 用户导出最终评分表，**Then** 系统生成带版本号和校验码的打印版表格。
2. **Given** 考核不属于当前用户的数据范围，**When** 用户通过编号尝试导出，**Then** 系统拒绝且不泄露考核内容。
3. **Given** 考核尚未进入待确认阶段，**When** 用户尝试正式导出，**Then** 系统提示当前结果尚未定稿。

---

### User Story 2 - 回录纸质签字 (Priority: P1)

具备考核审批权限的人员可以为待确认考核上传员工签字后的 PDF 或图片，登记签字日期和备注，并完成考核。

**Why this priority**: 纸质签字只有与具体结果版本绑定并可追溯，才能替代当前单纯的按钮确认。

**Independent Test**: 上传有效签字材料后，考核进入已完成，详情展示纸质确认方式、签字日期、经办人、版本和可下载附件。

**Acceptance Scenarios**:

1. **Given** 已导出当前版本且考核待确认，**When** 审批人员上传有效签字材料并登记日期，**Then** 系统原子性保存确认记录并完成考核。
2. **Given** 导出后结果发生变化，**When** 上传旧版本签字材料，**Then** 系统拒绝并要求重新导出。
3. **Given** 文件类型或大小不符合要求，**When** 用户提交，**Then** 系统不改变考核状态并给出明确错误。

---

### User Story 3 - 保留在线确认凭证 (Priority: P2)

员工继续使用现有“确认最终得分”按钮时，系统同时保存确认人、确认时间、结果快照、版本与校验码。

**Why this priority**: 在线确认和纸质确认应采用统一、可审计的记录方式。

**Independent Test**: 员工在线确认后，考核详情显示在线确认记录，且再次确认或修改结果被拒绝。

**Acceptance Scenarios**:

1. **Given** 员工本人的考核处于待确认且无未处理异议，**When** 员工在线确认，**Then** 系统保存在线确认凭证并完成考核。
2. **Given** 考核已经完成，**When** 任意用户尝试再次确认或修改评分，**Then** 系统拒绝操作。

### Edge Cases

- 没有导出过当前结果版本时，不允许登记纸质签字。
- 纸质材料只接受 PDF、JPG、JPEG、PNG，单文件最大 10 MB。
- 已提交且未处理异议时，不允许在线或纸质确认。
- 附件下载必须再次执行身份、权限和数据范围校验，不能通过公开静态地址访问。
- 上传数据库保存失败时必须清理已经写入的孤立文件；文件保存失败时不得提交数据库事务。
- 同一考核只能存在一个有效确认记录，重复请求必须安全失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 仅允许对 `pending_confirm` 或 `completed` 状态的考核生成正式最终评分表。
- **FR-002**: 最终评分表 MUST 包含员工与考核基本信息、每项最终得分、总分、总结评价、异议处理结果、签字栏、结果版本、导出时间和校验码。
- **FR-003**: 每次用于签字的结果版本 MUST 保存不可变结果快照；内容未变化的重复导出 MUST 复用同一版本，内容变化后 MUST 生成新版本。
- **FR-004**: 导出、查看确认记录及下载附件 MUST 在后端同时校验功能权限和考核数据范围。
- **FR-005**: 具备 `assessment:approve` 权限的用户 MUST 能为待确认考核登记纸质确认，且必须上传有效签字材料并填写签字日期。
- **FR-006**: 纸质确认 MUST 绑定当前结果版本；当前结果与最近导出版本不一致时 MUST 拒绝确认。
- **FR-007**: 员工在线确认 MUST 保存确认方式、确认人、确认时间、结果版本、结果快照和校验码。
- **FR-008**: 纸质确认 MUST 保存签字日期、经办人、原始附件名、受保护文件位置、备注及审计记录。
- **FR-009**: 确认成功 MUST 将考核及指标最终分原子性定稿为 `completed`，失败时不得产生半完成状态。
- **FR-010**: 已完成考核的评分、总分、总结评价和异议结果 MUST 禁止通过普通更新接口修改。
- **FR-011**: 页面写操作 MUST 显示提交中、成功和可操作的失败反馈，并在详情中展示确认方式、时间、经办人、版本和附件入口。
- **FR-012**: 本阶段 MUST NOT 实现最终评分 Excel 批量导入、电子手写签名或任意签批工作流。

### Key Entities

- **结果快照**: 某条考核在正式导出或在线确认时的不可变最终结果，包含版本、序列化内容、校验码、创建人和创建时间。
- **确认记录**: 一条考核的有效确认凭证，区分在线与纸质方式，并关联确认人、经办人、结果快照及纸质附件信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: HR 可在 2 分钟内完成一条考核的导出、打印准备和纸质签字登记操作。
- **SC-002**: 100% 的已完成新考核都能查询到确认方式、确认时间和对应结果版本。
- **SC-003**: 越权导出和附件下载测试均返回拒绝结果，且响应不包含受保护考核数据。
- **SC-004**: 无效文件、过期结果版本、重复确认和已完成结果修改均不会改变业务数据。
- **SC-005**: 打印版在常见 A4 打印设置下包含完整签字区域和可识别的结果版本。

## Assumptions

- 纸质签字由 HR 或绩效审批人员回录，员工本人不上传纸质材料。
- 本阶段输出 XLSX 打印版；签字材料支持 PDF 或图片，固定版 PDF 报表生成留作后续增强。
- 附件保存在应用受保护目录，由鉴权下载接口提供访问，不使用公开静态目录。
- 现有 JWT、权限目录、数据范围和 SQLite 自动迁移机制继续复用。
