## 2. 已实现能力

### 2.1 角色、权限与数据范围

- 已建立 User → Role → Permission → Data Scope 权限模型。
- 已预置七个系统角色：超级管理员、HR 管理员、绩效专员、部门负责人、评审人、
  数据分析员、普通员工。
- 已建立 Permission、RolePermission、UserRole、DataScope、RoleDataScope 数据模型。
- 后端路由已由 Permission 中间件保护，未授权访问默认拒绝。
- 已支持 `SELF`、`DIRECT_SUBORDINATES`、`DEPARTMENT`、`ASSIGNED` 和 `ALL`
  等查询范围。
- 超级管理员的角色变更、修改和删除具有额外保护。
- 前端侧栏和受保护页面按 Permission 显示和跳转。

### 2.2 员工管理

- HR 可以创建、编辑、停用和删除允许范围内的员工。
- 创建员工可选择系统预置角色、所属部门、直属上级和初始密码。
- 普通员工创建时必须选择直属上级。
- 初始密码和重置密码经过 bcrypt 哈希，不在 API 响应中返回。
- 创建和编辑操作具备提交中、成功和失败提示。
- 已验证普通员工和部门负责人创建后可以使用初始密码登录。
- 重复邮箱返回明确 `409`；普通员工选择停用或跨部门直属上级时返回明确 `400`。

### 2.3 数据隔离

- 普通员工只能访问自己的员工和考核数据。
- 部门负责人按部门范围查询员工与业务数据。
- HR、绩效专员或分析员按各自权限和数据范围访问数据。
- 公司级统计和报表接口具有独立 Permission 保护。

### 2.4 Docker 部署

- 后端映射端口：`13808 → 8080`。
- 前端映射端口：`13003 → 3000`。
- Nginx 统一入口：`http://localhost`。
- 健康检查：`http://localhost/health`。
- SQLite 数据和导出文件使用命名卷持久化。
- Nginx 配置已构建进独立镜像，避免本地单文件挂载兼容问题。
